V3 商家端页面级方案（基于 V2 链路迭代）

一句话：在 V2「Create AI LIVE」五步向导链路上做增量迭代（不重构），承载体验 / 商家输入 / 埋点回流三件事；脚本如何生产、如何自动迭代、provenance、diff、prompt、归因——商家全程无感（属平台端）。
硬约束：交互 / 配色 / 布局 / 字体严格沿用 产品方案.png + V2已实现功能与商家端视觉交互规范.md；图片识别统一 gemini-3-pro-preview-new（对商家透明）。

§3 Step 1 · Set up LIVE — 数字人人格卡画廊 + 直播国家/语言（核心增量① 【P0】）

V2 现状：LIVE name 输入 + 数字人卡片网格（试听 Listen 3s + 音色风格 Tag）+ 背景（Background templates / My own image 两 Tab）+ 右侧 9:16 预览 + Save/Next。

V3 增量：① 顶部新增 Market + Language（决定下游脚本/素材语言）；② 数字人卡片网格升级为人格卡画廊（Log 0009 维持"先选人"）；③ 语言联动过滤画廊。

UI 展示逻辑（中栏 · Set up LIVE，自上而下，控件全部沿用 V2）

  • ① LIVE basics（沿用 V2 表单区）
    • LIVE name：单行文本输入（V2 既有）。
    • 🆕 Market ▾（直播国家，下拉）：本期仅 United States (US) 单选且默认选中、置灰不可改（为未来多国预留）。
    • 🆕 Language ▾（直播语言，下拉）：两项 English / Spanish，默认 English。ⓘ 帮助气泡说明"决定口播语言与可用数字人，一场一种语言不可混播"。
      联动：切换 Language → 下方人格卡画廊即时过滤，仅显示支持该语言的形象/音色；若已选数字人不支持新语言 → 二次确认弹窗提示清空已选。
  • ② Choose avatar hosts（人格卡画廊）
    • 筛选器条（沿用 V2 表格筛选样式）：品类 Category ▾（默认值平台预选：注册主营类目 / 近 30 天动销额最大类目；可改）、族裔 Ethnicity ▾、价格带 Price tier ▾。语言不在此处选（已上移为 Language ▾ 并联动过滤）。右侧 See more。

    • 选中后右侧 9:16 预览实时换该数字人底板。
  • ③ Set up LIVE background（沿用 V2 两 Tab）：Background templates / My own image，可选卡片 + See more + 上传 dropzone。此处即"全局背景"入口。
  • ④ 底部操作条：Save（次）/ Next（teal 主，右下）。

商家输入新增

  • 🆕 Market（US，本期固定）+ Language（English / Spanish）：核心前置输入——决定下游脚本口播语言、合规口径、素材 ASR/打标语言、数字人音色（进平台端 shared_context.market / language）。一场一语言不可混播（Log 0022）。
  • LIVE name（V2 既有）。
  • 数字人形象选择（V2 既有，体验升级为人格卡；受 Language 联动过滤）。

图片识别点（平台侧，商家无感）

§4 Step 2 · Select product（选品）· 增量（轻）【P0】

V2 现状：+ Add products + 表格（Product 图+名+ID / Price / Stock / Item sold / Remove）+ Save/Previous/Next。

V3 增量 · 核心原则：作为 TikTok Shop US 平台方，商家在架可售商品平台数据库全部覆盖——商家选完商品后，商品标题 / 价格 / 品类 / 描述 / 图片 一律不需要商家填写，平台结合所选商品从商品数据库自动带出。不存在"库里没有的品"，故全程无任何商品信息手填入口。 商家端只做"选品 + 卖点/禁讲两处选填增强"：

  • A. 选品（V2 既有 + Add products）：选中后图/名/ID/Price/Stock/品类/描述/图片 全部由商品库自动带出，商家零填写，展开行只读展示（可纠错但非必填）。
  • B. 卖点 / 禁讲（唯一两处商家"可选输入"，强烈建议填）：行内点 ▸ 展开 More settings，仅承载两列：
    • Selling points / 卖点备注（多行文本，选填、强烈建议填）——"必须讲的卖点"。商家最懂自家商品。
    • Do-not-say / 禁讲内容（多行文本，选填、强烈建议填，红色 ⓘ"将作为合规与生成约束"）——"不能讲的"。
    • 📌 价值锚点（记忆库）：卖点/禁讲连同人群洞察沉淀进商家记忆库复用。例：英国卖 57 英镑手机，直播间常问"能否在非洲用"，回查留评账号多为非洲用户→沉淀"非洲专场"文案因子，下次自动复用。
卖点/禁讲是商家端"可选必要输入"，消费方在平台端（进解析与生成 prompt 约束、合规左移 + 记忆库沉淀），商家端只采集、不展示如何被使用。

埋点回流：s2_product_add / s2_product_remove / s2_sellingpoints_edit / s2_donotsay_edit。（商品信息全部由平台带出，无商家编辑埋点）

§5 Step 3 · Set up scenes — 点开素材库弹框（核心增量② 【P0】模式一 / 模式二合并入 Storyboard）

V2 现状：三栏（左 LIVE Flow / 中 Set up scenes 的 Scene 卡 / 右 9:16）；Scene 卡二选一 radio：Use avatar（方式1 三层合成）/ Use your video（方式2 商家素材）；Overlay foreground 上传；浅绿"AI 已自动生成 storyboard"banner。

左栏 LIVE Flow 结构约定：一场直播 = 一个开场文案 + 商品列表 + 一个结尾文案；Set up scenes 围绕一个品的多个卖点展开，一个卖点 = 一个 Scene。即 Opening → 品1(Scene×N) → 品2(Scene×N) → … → Closing。

V3 增量：在 V2 的两个上传/选择入口上挂载素材库弹框（不改三栏布局、不改二选一逻辑）。方式1 与方式2 打开的是同一个素材库弹框（同一份商家素材库，不是两个独立弹框）：

  • 方式1 子行 Background: 🪑Default ✏️ → 点 ✏️ 打开素材库弹框。
  • 方式2 Use your video → 点缩略图区/Upload 打开同一个素材库弹框。

素材库弹框（复用 V2 弹窗 + 可选卡片 + dropzone + 分页）

  • 无平台公共库（不设 Templates Tab），弹框内全部是商家自有素材。方式1/方式2 共用此弹框，按素材类型分两个 Tab：
  • Tab① Raw 原始素材（类型1）：未加工原片——方式1 Background 上传视频 + 方式2 Use your video 上传视频（二者都算视频素材，同一条既可当前景也可当背景）+ 商家 TikTok 账号已发布短视频。
  • Tab② Clips 视频片段（类型2）：平台对"类型1 原片 + 直播录屏"做自动分镜+画面理解+打标后产出的 clip 维度素材。
    • clip 详情：卡片可展开/悬浮看——时长、主打商品卖点、推荐用途、匹配度，商家不必猜这段在讲什么。
    • 商家备注反馈：商家可对某条 clip 添加备注（如"这段口播很好/这段背景偏暗"）回流平台 = 除"改脚本→Save"外的第二条喂数据通道。
  • 顶部语义搜索框：输入关键词（卖点/场景/品类）跨 Tab 检索，尤其 Clips 片段极多时商家不用逐页翻。
  • （规划，V3 暂不开放）Creator videos：达人为商家商品带货产生的视频——属他人内容，需达人逐条授权方可入库，列为后续扩展（见平台端 §2 授权说明）。
  • 网格：可选卡片（选中 teal+✓）+ 缩略图右下 时长 badge + 标题（Clips 卡额外展示 推荐用途/匹配度）。
  • 右上 + Upload（dropzone：虚线框 + ↑ + 规则提示，沿用 V2 方式2 规范 MP4 ≤700MB / 5s~15min / ≥1080p / ≥24fps / H.264）。
  • 上传去重校验：上传时做重复度校验，历史已传过则不重复入库，直接标出该素材历史上传时间，无需重传。
  • 上传后显示进度条 + 自动校验 ✅❌，解析中显示 Processing（蓝）。
  • 底部 Cancel / Use selected（teal）。
  • 删除/替换/切换方式 1↔2 → 二次确认弹窗（提示将清空已配置三层布局/素材/清洗稿）。

画面布局模型（V3 = 把 V2 三层从"固定参数"变成"商家可调"）

沿用 V2 9:16 拖拽预览 + X/Y/Scale slider，不新造控件。V3 不做 4 类 layer 用途下拉、不做 PIP 画中画，只把 V2 已有三层 + 数字人位置开放为商家可调：

  • 全局背景层（在 Step1 设置，Step3 不设入口）：直播间维度背景图/视频统一在 Step1 · Set up LIVE 的 Background 环节设置（含背景视频）；贯穿整场、独立于单个 Scene；某 Scene 无背景素材时回落到 Step1 的直播间背景；视频则循环。
  • 三层 + 数字人位置（V3 核心：固定 → 可调）：
    • 背景层：Scene 选用的背景素材（方式1 视频/图）；
    • 中景 ＝ 数字人：位置 X/Y/Scale 可拖拽调整；
    • 前景贴图层（Foreground）：X/Y/Scale 可拖拽（V2 既有 Overlay foreground 能力）。
  • 层级叠放顺序（预览与渲染一致）：前景贴图 / 数字人 / 背景素材 / 全局背景。
与 V2 关系：V2 已有"远/中/前景三层 + X/Y/Scale"，但 V2 是固定参数、商家不可调；V3 的唯一核心增量就是把这三层 + 数字人位置的调整能力开放给商家，不引入 PIP、不引入 layer 用途选择。选中某 Scene 调整布局时，右侧 9:16 Preview 实时渲染同步，所见即所得。

商家输入新增

  • 素材上传（方式1 Background + 方式2 Use your video，二者都算视频素材，体验收敛进素材库弹框）。
  • 画面布局：背景层素材 + 数字人位置 + 前景贴图层 的 X/Y/Scale 调整（全局背景在 Step1 设置）。
  • 给平台的"悄悄话"（左栏 LIVE Flow 顶部新增一处选填，多行文本）——文案改为「💬 给平台剧本安排的悄悄话」：商家对"整场怎么播"的偏好喂给平台，表达轻松有趣，并沉淀进商家记忆库后续复用。

图片识别点（平台侧，商家无感）

  • 商家上传素材 / 直播录屏 / TikTok 已发布短视频 → 平台侧 gemini-3-pro-preview-new 自动分镜 + 画面理解 + 打标 → 回填到 My assets 网格。商家端只看进度与结果卡片。

§6.5 模式二 · LIVE Storyboard（Step3+Step4 合并为一步 · timeline 视图）【P2】

本节属模式二（智能剧本），把 §5 Set up scenes 与 §6 Generate scripts 合并为一个时间轴页，由平台端 Script Studio 主-子 Agent 编排驱动（详见平台端 §3）。架构本期先设计，实现后置 P2；商家选模式二后进入此页（P2 上线前卡片置灰 Coming soon）。Step5 维持不变。

⭐ 核心模型：同一时间轴、多轨道叠加（NLE 式）。这是剧本最核心的能力——任一时刻可多轨同时生效（如某 30s 内：轨1口播 + 轨2画面 + 轨5场外音催单 + 轨6铃声同时响），不是"一轨接一轨顺序播"。详见下「多轨并发模型」与平台端 §3 直播大脑 JSON schema 契约。

UI 展示逻辑（中栏 · LIVE Storyboard，横向时间轴，多轨泳道）

  • 泳道布局：横向一条绝对时间轴（秒），每条轨道一条独立 lane；先在轴上给每个品分配时间段，品内再排 Scene；各轨原子是 lane 上色块，带显式起止 [start,end]，可拖拽改时点/时长、可在同一时间窗重叠。
  • 轨道① Speech 口播：Hook / Body / CTA 段（pill 沿用 V2 灰），可编辑 ✏️；命中违禁词 highlight。Scene 展示时长 = 该段口播 TTS 时长驱动（§6.6）。
  • 轨道② Visual 画面：方式1 三层布局缩略 / 方式2 scene 素材 clip（商家在 Use your video 上传的预录视频片段，画面走该 scene、TTS 解说不断），与素材库联动只读展示。"画中画"效果用三层实现——数字人作中景缩小+定位、素材铺背景或全屏覆盖，不引入独立 PIP 控件；画面状态对应 visual.layer：none（数字人+背景同框）/ foreground（素材全屏、数字人隐）/ background（素材铺背景）。
  • 轨道③ Interaction 互动（独立模块）：互动不绑定到每个 Scene，抽成独立互动配置模块，按整场 / 商品维度统一配置；时间轴只读展示落点，统一 on/off。
  • 轨道④ Operation 运营 ＝ 品级 overlay 层：每个品一个 overlay 层，层内可放多张图片元素（商品实拍图贴前景"桌面"、价格牌/秒杀价/倒计时贴片贴画面左侧）。各元素 X/Y/Scale 可拖拽，元素种类不封顶，由商家自行判断。与时间轴联动，只读+开关。
  • 轨道⑤ Voice 声音：默认带 Step1 所选数字人音色；理想态支持按商品差异化声纹/语速（本期占位）。
  • 轨道⑥ Off-screen 场外音（强化真人在场，对冲红线 #15）：任意时点 + 加场外音原子，二选一：① 音效库 SFX（铃铛🔔/掌声/上新提示音/倒计时滴答…）；② TTS 语音播报（输入文案→选播报音色，可与主播不同＝第二人声→平台生成）。每原子可设触发时点（对齐时间轴/绑定某 Scene/运营节点）、音量、是否压低 BGM（ducking）。
  • Scene 卡头部保留 ⏱ Estimated Duration + 预估脚本字数。

⭐ 多轨并发模型（同一时间轴叠加 · 渲染契约，与平台端 §3 schema 一致）

  • 层级：主时间轴(整场) → 品时间段 → 品内 N 个 Scene → 每条轨道独立泳道；原子 {track, start_sec, end_sec, payload}，靠绝对时间对齐、可重叠。
  • 视觉合成（z-order，上→下）：① 运营 overlay 元素 ② 前景贴图 ③ 数字人（中景，缩放+定位 ＝ 画中画来源）④ 背景素材（scene clip）⑤ 全局背景。
  • 音频混音（优先级 + ducking，高→低）：① 口播 > ② 场外音 TTS（第二人声）> ③ SFX/铃声 > ④ BGM；高优先级活跃时自动压低低优先级。
  • 示例（并发）：t=0~8s 轨1口播+轨2画面(数字人画中画)+轨3互动 → t=8~12s 轨1口播+轨5场外音催单+轨6铃声(BGM duck) → t=12~18s 画面切轨2全屏素材(引导下单, layer=foreground) → t=18s+ 轨1口播+轨2背景视频(layer=background)。
  • 商家编辑形态：拖品时间段 → 拖品内各轨原子 start/end → 右侧 9:16 实时按合成/混音契约预览。

唯一"喂数据"动作 = 改 → Save（同模式一）

  • 商家在口播轨编辑、开关互动/运营/场外音原子 → Save 回流平台；diff/归因全在平台端，商家无感。

埋点回流：s4_script_edit、s4_interaction_toggle/s4_operation_toggle（atom_id、on/off）、s4_overlay_edit（品 overlay 元素增删/拖拽）、s4_offscreen_add（type=sfx/tts、触发时点）、s4_compliance_hit、s4_save。全部带 mode=smart 维度，供平台端按模式归因。

§6.6 Scene 时长由 TTS 驱动（两模式通用）

  2. method2_use_your_video：商家通过 Use your video 上传的前景素材（方式2，对应 layer=foreground）；
  3. live_replay：直播录屏解析分镜（仅产 clip，属类型2）；
  4. tiktok_post：商家 TikTok 账号已发布的短视频（自有账号，授权拉取后自动分镜）。
两类映射（与商家端 §5 两 Tab 一致）：类型1（原始）= method1_background + method2_use_your_video + tiktok_post 原片；类型2（clip）= live_replay clip + 对类型1 解析出的 clip。同一条原片可同时用作前景或背景。

match_score商品匹配度（0–100，meter 进度条）。比对集 = 该商家近 30 天有动销的商品全集（含商家端历史已选商品）；逐 clip 对该集算匹配度
recommend_use推荐用途（建议 layer：background/foreground/none；foreground↔方式2、background↔方式1。不含 pip，V3 已砍 PIP）
visual.layer底层渲染字段（保留）：{background, foreground, none} 供渲染引擎决定叠放（商家端不暴露，仅平台/渲染用；V3 已移除 pip）
format标准化产出格式：MP4 / 5s–15min / ≤700MB / 1080×1920 / ≥24fps / H.264——产 clip 时即转码达标，商家端可直接复用
tags品类 / 卖点 / 场景标签
duration时长 badge

§3 📝 Script Studio · 剧本生产台（链路二：JSON 生产 + provenance + 合规左移）【P2】

优先级【P2】：主-子 Agent 智能编排剧本生产改动量大，作为后置 P2；架构本期先设计好（双 prompt / 共享上下文 / provenance / 画面层级模型），实现随商家端模式二一起落地。
⚠️ 与模式一的关系：模式一（P0）Step4 脚本用的是 V2 既有脚本生成能力，不依赖本台的主-子 Agent 编排；本台编排是模式二（P2）的生产后台。
★ 双 prompt 优先级分层（Log 0025）：① 理解 prompt（素材打标）随 Material Studio 进 P0（模式一也要素材加工）；② 生成 prompt（剧本编排）随本 Script Studio 进 P2。

职责：以主-子 Agent 编排模型产出"直播大脑 JSON"——L0 整场主 Agent 编排开场/品序/结尾/全局，6 条职能 subagent（选品/脚本/画面/互动/运营/声音/场外音）横切整场、共享上下文、并行产出后对齐同一时间轴；并写 provenance、做合规左移。这是商家端 Step4 LIVE Storyboard 的生产后台（编排模型对商家无感）。

页面布局（按 商家ID + 直播任务ID 组织）

  • 顶层导航 = 商家 Shop ID → 直播任务 task_id（对应商家端创建的每个直播任务）；选定某任务后才进入下方左/中/右三栏。
  • 左：直播大脑 JSON 结构树 = L0 主 Agent（Opening / Product 序 / Closing / 全局风格）→ 6 职能 subagent（选品/脚本/画面/互动/运营/声音/场外音）；选品 subagent 下展开 品 → 卖点 Scene → hook/body/cta 时间轴。
  • 中：JSON 编排视图（时间轴 + 多轨道原子卡）+ 双 prompt 面板（① 理解 prompt ② 生成 prompt，只读展示当前版本，编辑入口在 Workflow Studio）。
  • 右：provenance 抽屉——每个原子展开可见：所属 agent_role/track、来源 prompt 版本、生产阶段、引用的 Clip Bank 资产、命中的卖点/禁讲约束、合规检查结果。

★ 双 prompt 定义 + 剧本生产触发时机

  • ① 理解 prompt（Understanding）：作用对象 gemini-3-pro-preview-new（多模态，看视频/图片），在 Material Studio（链路一） 对素材做自动分镜+画面理解+卖点/场景/品类打标+封面优选，结构化成 Clip Bank（visual 即其产物）。决定素材理解得准不准。
  • ② 生成 prompt（Generation）：作用对象纯文本 LLM（不在图片识别替换范围），在 Script Studio（链路二） 把 Clip Bank + 商家输入(卖点/禁讲/悄悄话) + 商家选中的商品列表 + 平台红线 组装产出直播大脑 JSON，并触发合规左移、写 provenance。决定剧本好不好、合不合规。
  • ★ 剧本生产触发时机（重大修正·很关键）：生成 prompt 的核心输入是商家选中的商品列表，因此剧本生产在商家端 Step2 选品完成、点"下一步"离开 Step2 时就立刻触发（后台异步）——不是等 Step3 结束进 Step4。Step3 的素材/scenes/悄悄话作为后续增量重生成的输入。这样商家进入 Step3/Step4 时初稿已就绪，体验更顺。

★ 主-子 Agent 编排模型 + 共享上下文 schema（Log 0014–0016 落地）

L0 整场主 Agent（= 一场直播 = 商家端一个直播任务）
  产出：开场 / 品序编排 / 结尾 / 全局风格调度
  ├─ 选品 subagent     一品 N 卖点(Scene) → 品级小剧本（带时间轴 = 直播大脑 JSON）
  ├─ 脚本 subagent     口播 hook/body/cta
  ├─ 画面 subagent     visual.layer{bg/fg/none}（已砍 pip） + clip 引用
  ├─ 互动 subagent     整场 / 商品维度（独立模块）
  ├─ 运营 subagent     商品维度（价格牌 / 秒杀 / 楔子，联动 overlay）
  ├─ 声音 subagent（V3 规划占位）   音色 / 语气 / 语速（TTS）
  └─ 场外音 subagent（V3 规划占位） 旁白 / 场控 / 助播 / BGM（强化真人在场·对冲红线 #15）
  调度：各 subagent 并行产出 → 主 Agent 对齐同一时间轴（并行 ≠ 无依赖：读彼此「已产出原子」，不读中间过程）

为什么并行：互动/脚本/画面/声音/场外音各由独立 PM 设计、各有独立测评 rubric，天然解耦；主 Agent 是编排器/协调者，不做串行流水线。

共享上下文 schema（随直播大脑 JSON schema 一起落，不单独成稿——Log 0017）：

层谁可读内容
shared_context全 subagent 可读（字节稳定前缀）market（US）/ language（en/es）/ mode（classic/smart）、商品列表（近 30 天动销可选集）、人设/avatar、商家记忆库、整场节奏/品序、平台红线、商家"悄悄话"
track_private各 subagent 私有该轨 directive + 专属参数（声音 TTS / 画面渲染…）+ 读权限白名单（如声音轨不读 match_score / 视觉标签）
track_outputs轨间共享产物层各轨已产出、对齐时间轴的结构化原子；按需引用解决数据依赖，不读中间过程
借鉴 Claude Code 多 Agent 机制：shared_context 字节稳定前缀 ≈ fork 复用 prompt cache；track_private 读权限白名单 ≈ 工具白名单做能力隔离；"只交换产物、不偷看中间过程" ≈ 防上下文污染。

provenance 落点（Log 0005 敲定 + Log 0015 扩展）

  • 独立表 + JSON 引 id：脚本 JSON 内每个原子带 provenance_id，溯源明细存独立表（便于跨场聚合归因）。
  • 字段：agent_role（orchestrator(L0) / track-subagent）、track（selection/script/visual/interaction/operation/voice/offscreen）、mode（classic/smart，Log 0024）、market / language（Log 0022）、prompt_ver / stage / referenced_clip_ids / selling_points / donotsay_hits / compliance_flags / gen_time。归因精确到"哪条职能轨道的哪个 subagent"。

画面层级模型（visual.layer = 底层渲染字段，保留；商家端不暴露）

  • 直播大脑 JSON 中每个画面原子带 visual.layer ∈ {background, foreground, none}（V3 已砍 pip；商家端只感知"三层+数字人位置可调"，此字段仅供平台/渲染引擎使用）：background 铺满并临时替换全局背景 / foreground 全屏覆盖（优先级高于默认前景贴图）/ none 仅默认背景+数字人+默认前景。
  • 全局背景层（global_background）：场次级字段，贯穿整场；某原子无 background 素材时回落全局背景；视频则循环。
  • 运营 overlay 层（V3：品级 + 多元素）：每个品一个 overlay 层，含多个元素 {type: product_image | price_tag | flash_sale | countdown, x, y, scale}，元素种类不封顶；运营 subagent 产出、与时间轴联动。
  • 渲染按"画面布局种类数"调用慧播星底板（0/1/≥2，见 §8）——layer + 全局背景 + overlay 决定底板段数。

⭐ 直播大脑 JSON · 多轨并发时间轴 schema 契约（剧本最核心 · 同一时间轴多轨叠加）

这是剧本/Storyboard 的最核心数据契约：同一条绝对时间轴上多条轨道叠加、任一时刻可多轨并发（非顺序播）。编排端（Script Studio）产出、渲染端、商家端 §6.5 编辑三方共用同一契约。已同步写入 .cursor 项目约束。
{
  "timeline": {
    "total_duration_sec": 0,                 // 由各 Scene TTS 时长累加驱动
    "products": [                            // 主时间轴先切成"品时间段"
      { "product_id": "...", "start_sec": 0, "end_sec": 0,
        "scenes": [ { "scene_id": "...", "start_sec": 0, "end_sec": 0 } ] }
    ],
    "tracks": {                              // 每条轨道=独立泳道；原子带显式 [start,end]，可重叠
      "speech":      [ { "atom_id","scene_id","start_sec","end_sec","segment":"hook|body|cta","text" } ],
      "visual":      [ { "atom_id","start_sec","end_sec","layer":"none|foreground|background","clip_id","avatar_pos":{"x","y","scale"} } ],
      "interaction": [ { "atom_id","start_sec","end_sec","scope":"live|product","type":"comment|qa" } ],
      "operation":   [ { "atom_id","start_sec","end_sec","overlay":[{ "type":"product_image|price_tag|flash_sale|countdown","x","y","scale" }] } ],
      "voice":       [ { "atom_id","start_sec","end_sec","voice_id","rate" } ],
      "offscreen":   [ { "atom_id","start_sec","end_sec","kind":"sfx|tts","payload","gain_db","duck_bgm":true } ]
    },
    "render_contract": {
      "visual_zorder":  ["operation_overlay","foreground_sticker","avatar","scene_clip","global_background"], // 上→下
      "audio_priority": ["speech","offscreen_tts","sfx_bell","bgm"],                                          // 高→低
      "ducking": "higher-priority active → attenuate lower（口播/场外音起 → BGM 自动压低）"
    }
  }
}
  • 绝对时间对齐：所有轨原子用 start_sec/end_sec 定位，不靠数组顺序；多轨可同一时间窗重叠（speech+offscreen+sfx 同时）。
  • 视觉合成：按 visual_zorder 自上而下合成；"画中画"＝ avatar 缩放定位叠在 scene_clip 之上（用三层实现、无独立 PIP）。
  • 音频混音：按 audio_priority + ducking 混音，口播/场外音优先、BGM 自动让路。
  • provenance：每原子带 provenance_id（含 track + mode），并发原子逐一可溯源/归因。
  • 驱动关系：scene.end_sec - start_sec 由该 scene 口播 TTS 时长决定（商家端 §6.6）。

合规左移 / 数据流

  • 生成时即把平台治理红线（见 TikTok平台治理与风控规则知识库.md §9/§10）+ 商家"禁讲内容"注入生成 prompt；命中项打 compliance_flags，在原子卡标注（内部可见，商家端只看高亮）。

        → L0 主 Agent 编排 + 6 职能 subagent 并行产出（共享上下文）
