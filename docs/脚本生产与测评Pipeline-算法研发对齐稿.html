0 全景数据流

脚本生产与测评 = 输入 → 生成 → 测评闭环三段式。本页按数据流主线组织，给算法 & 研发对齐每个模块的输入/处理/输出/依赖/接口契约。

🏭 全链路属于 平台端（生产+智能层）· 商家无感 ｜ 商家仅 2 个触点： ① 录入商品卖点 ② 改稿→保存（反馈）

三条设计原则

事实域 vs 生成域API 给结构化事实；痛点/场景/差异化亮点由 LLM 在事实上推理生成。
生成与测评拆开卖点生成、卖点测评是两条解耦链路；不绑定"五点详描"接口。
双端归位三步全在平台端，商家无感；后台术语不外露到商家端。

1 信息获取 · 三角输入

三个互补维度：客观事实、商家主观意图、画面素材。下方为各源的来源 / 用途 / 真实样例。

事实 信息1 · 商品基础域 API

  • 来源：GEC oec.product.product_detail
  • 用途：商品/品类特点、价格、物流、售后、合规校验依据
  • 样例：见 §4 最小字段集契约

意图 信息2 · 商家录入卖点

  • 来源：商家创建直播、选品后主动录入
  • 用途：商家最懂品的卖点意图（"喂数据"通道）
  • 注意：不可直接采信，须合规校验（见下）

素材 信息3 · 最强相关 clips

  • 来源：平台解析的 Clip Bank（gemini-3-pro 分镜）
  • 用途：决定 visual 轨；卖点配画面
  • 样例：见 §4 Clip Bank 契约（含 match_score）

信息1 详解 商品基础域 API · 能拿到什么（事实域全清单）

以下字段全部可从 GEC oec.product.product_detail 取到，是脚本生产最确定的输入。 来源：商品基础域对外API文档.md §3 字段分类总表。按需取，勿传 all（单商品完整信息十几 K）。

业务域能拿到的关键字段脚本可用点取数方式
① 商品基础 name images white_background_image video html_desc · category_detail/categories_v2/fe_category · brand/universal_brand/brand_detail · product_properties sale_properties attributes · manuals size_chart_data 商品&品类特点、画面取图、规格参数、品牌背书、怎么用/怎么选 product_fields；类目/属性直传；size_chart_data 需 options.need_size_chart_data
② 价格 min_sale_price max_sale_price · sku_price channel_sku_price combo_sub_sku_price · fee(押金) 报价/价格锚点、多规格报价 区间→product_fields；SKU 价需 options.need_sku_price=true
③ 营销/卖点料 selling_point(卖点原料) · sold/sold_l30d/global_sold/product_sales · sales_tags · gift · quality · first_image_detail · product_tags 卖点生成输入、热卖背书、赠品促单、选图 selling_point→extension.selling_point；销量需 options.need_product_sale=true
④ SKU规格/库存 skus property_pairs skcs · sku_quantity product_stock_status all_stock_status · bundle_ids combo_sub_skus 多规格讲解、避免讲断货品、套餐话术 skus+sku_fields；库存需 need_sku_ids(+need_stock_quantity)
⑤ 物流/履约 dimension_v2 weight_v2 package_* · sale_modes is_pre_order/pre_order_type fulfillment_info · cod_status · shipping_insurance_type 大件/轻巧、现货/预售/即时达时效、货到付款、运费险 product_fields（V2 经 i18n 单位换算）
⑥ 售后 warranty_period warranty_policy · manuals packing_list · purchase_limit_rules 保修安心话术、开箱含什么、避免超量承诺 product_fields；限购需 options.need_purchase_limit_rules
⑦ 合规/资质 qualification_info product_qualifications · manufacturer_info_v2 rp epr · hazmat · age_limit · gtin 功效/认证话术合规依据、未成年带货红线(age_limit) product_fields；制造商/责任人需对应 options.need_*
⑧ 状态/业务标识 product_status regional_product_status · biz_type sale_type platform product_source · sale_region/salable_regions · first_live_time 过滤不可售品、决定可取字段差异、"新品"话术 状态需 options.need_product_status（受 region）
默认基础包（所有品类必取）： name · images · category_detail · min_sale_price/max_sale_price · product_status · sale_region。 其余按品类侧重叠加（美妆→成分/功效/资质；服饰→颜色尺寸/size_chart；家居家电→规格/尺寸重量/保修…）。
⚠️ 价格口径红线：本 API 仅原价；活动价/营销价属营销中心（另接），脚本涉及促销价须另接营销域，规避误导价格。
⚠️ 冲突与合规校验（必做）：信息2（商家说"祛斑神器"）可能与信息1 ⑦合规资质域（qualification_info 无功效认证）冲突。 流程：商家录入卖点 → 过【信息1 事实域 + ⑦资质域】校验 → 采纳 / 降级 / 拦截。功效、价格类卖点必须有信息1 字段支撑，规避误导功效/价格红线。

① 商品排序

输入
动销商品集 + 信息1：②价格(min/max_sale_price)、④库存(product_stock_status)、③销量(product_sales/sales_tags)、⑧首发(first_live_time) + 商家备注
处理
规则加权打分 + 模型CTR/CVR 预估微调 + LLM仅做节奏微调（开场强品/中段铺量/尾部逼单），非纯生成排序
输出
[{product_id, rank, time_slot, score, reasons[]}]
依赖
信息1（价格/库存/销量）+ 信息2 + [记忆域：历史高转化排品]
provenance · 排序口径
记录各信号得分+权重：转化潜力(销量/CTR预估) · 价格带分布 · 库存深度 · 新品加权 · 毛利(若可得) · 商家指定置顶。每品输出 reasons[] 可溯源

② 卖点池生成（链路A · 与测评解耦）

输入
信息1：③selling_point + ①product_properties/sale_properties/category_detail + ⑥warranty_* + ⑦qualification_info；信息2 商家卖点(校验后)
处理
LLM按品类全覆盖逐维度产出短卖点（单点短表达）；痛点/场景/差异化亮点在此由 LLM 推理生成（生成域）
输出
卖点池 SellingPoint[]（每条带 category_dim + evidence[]，结构见 §4）
依赖
①品序；品类卖点侧重配置表（按品类裁剪维度）
provenance
每条卖点 evidence[] → 信息1 字段 / 信息2 录入 / 信息3 clip

③ 卖点 × clip 匹配 核心一环

输入
②卖点池 + 信息3 Clip Bank（visual_zh/tags/clip_type/highlight/asr_lang）+ 信息1 ①images/video(兜底)
处理 · 算法倾向
多模态语义匹配为主：卖点 text embedding × clip(visual+tags) embedding 余弦相似 → 基础分；规则加权：clip_type=strong↑、highlight=true↑、asr_lang 与 shared_context.language 一致↑、时长适配↑
输出
{sp_id → {clip_id, match_score(0-100), layer:foreground|background}}
依赖 · 阈值兜底
②卖点池；match_score≥阈值(如70)采纳，否则兜底用商品主图/白底图(信息1①)；一卖点可配多候选 clip
provenance
match_score + Top-N 候选 clip 列表 + 命中规则项

④ 短卖点脚本（卖点→口播话术）

输入
卖点（含支撑事实）+ 人设/语言 + 痛点/场景(生成)
处理
LLM生成口播；时长由口播 TTS 驱动
输出
speech 原子：hook/body/cta + text
依赖
②卖点池；shared_context.language(en/es)
provenance
脚本→卖点→事实链路

⑤ 专场文案（场次级）

输入
①整场品序 + 主题/活动(信息2) + 人设/语言(shared_context) + 信息1 ③gift/sales_tags
处理

输出

依赖
①品序；④脚本（保证口径一致）
provenance

3 测评闭环 · 双层

测评不是一次性打分，而是「生成前门禁 + 上线后归因」双层，结果回流迭代 prompt 形成闭环。

前 生成前门禁（pre-flight）

出稿即测：脚本质量分（脚本测评标准2.0）+ 合规左移校验 → 不达标不放行。

↓   ↑ ↺

后 上线后归因（post-hoc）

直播中/后：分钟级双视角归因、转化回流、商家保存稿 vs 平台初稿 diff（平台侧分析、商家无感）→ 回写迭代 prompt。

测评对象分层（粒度不同别混）：卖点 / 脚本 / 剧本三层各自评，与生成链路解耦。
测评对象层测评维度（定稿）
卖点
（链路B）		生成前 ① 品类覆盖度：是否覆盖该品类应讲维度（功效/材质/场景…）· ② 事实准确性：是否有 evidence[] 支撑、与信息1 一致 · ③ 合规性：功效/价格是否越界（资质域校验）· ④ 表达质量：短、口语、单点聚焦 · ⑤ 去重/差异度：卖点间不重复
脚本
（口播话术）		生成前 复用 脚本测评标准2.0（V2 基线·第六部分）：相关性 / 卖点还原 / 流畅自然 / 合规 / 行动引导（CTA）； 叠加 TTS 时长适配（与 scene 时长匹配）·语言一致性（asr_lang vs language）
剧本
（整体）		前 + 后 前：结构完整(品/scene/轨齐全) · 时间轴合法(原子 [start,end] 不越界、z-order/混音契约可渲染) · 卖点↔clip 匹配率 · 后：分钟级转化/互动效果 · 保存稿 diff 偏离度
